# 我的生命蓝图 · 独立 Writing Layer Prompt

> 这份文件只负责**「我的生命蓝图」最终呈现给使用者的文字表达方式**。
> 占星计算、星盘资料来源、行星权重、宫位与相位判断、命主星、日月升、各章判断逻辑、
> 内容分类、主题定调、个人化生成方式、JSON / database structure —— 全部不动。

---

## 1. 这段 Prompt 该放在哪里

生命蓝图的 Prompt **不在这个仓库里**。仓库(`app.html`)只负责把资料送出去:

```js
// app.html:2288
askServer("blueprint", withSource({}, chart, "blueprint", null, forceLang), res, fpSeed, parseChapters, forceLang);

// app.html:2238 → POST 到 Supabase Edge Function
const FUNC_URL = SUPABASE_URL + "/functions/v1/read-chart";
body: { kind: "blueprint", fingerprint, chart, lang, source? }
```

Prompt 与九步定调都在 **Supabase Edge Function `read-chart`** 里面,依 `kind` 分派:

| `kind` | 用途 | 这次是否修改 |
| --- | --- | --- |
| `blueprint` | 我的生命蓝图 | **只改这一支** |
| `topic` | 主题解读 | 不动 |
| `map` | 人生地图 / 详细解读 | 不动 |
| `question` | 单题解答 | 不动 |

**落地方式:在 `read-chart` 里为 `kind === "blueprint"` 建立一支独立的 `buildBlueprintPrompt()`,
用下面第 4 节的内容整段替换原本的 blueprint prompt。不要改动 shared prompt 或其他三个 `kind` 共用的任何部分。**

如果目前四个 `kind` 共用同一个 prompt builder,请先把 blueprint 拆成自己的分支再替换,
避免 topic / map / question 受到影响。

## 5. 与旧版逐条对照

| 项目 | 旧版 | 新版 |
| --- | --- | --- |
| 定位 | 「帮助他认识自己的生命蓝图」 | 加上明确定位:比主题解读更轻、是认识自己的入口,不是主题解读的浓缩版 |

## 6. 落地后建议的验收方式

拿 2–3 张差异明显的既有星盘(例如:元素严重偏重的一张、指针分散的一张、有 T 三角的一张)
各生成一次,然后逐条对:

1. 正文里搜「座」「宫」「相」「行星」「星盘」「能量」「课题」「疗愈」「宇宙」—— 应该零命中。
2. 把星座名遮掉念一遍 —— 还像在写这个具体的人吗?
3. 随便挑两段,看有没有在讲同一件事。
4. 手机宽度下看 `body` —— 有没有超过 4 行不换段的地方。
5. 五章各自回答的问题有没有跑掉(外在的那章有没有跑去讲内在)。
6. 三张盘的输出彼此之间够不够不一样(不一样才代表判断深度没被稀释)。
