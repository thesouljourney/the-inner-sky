## 1. 这份「锁」不是一句宣告

| 钉住的东西 | 指纹 |
| --- | --- |
| 判断用的词表 | `52eaf14835ee7076` |
| 已锁样本 `RAW_V12.C1` 的完整推导结果 | `3b48592c7de80a85` |
| `CALLS_WINS` 合成样本的完整推导结果 | `77f1fc2f861c052c` |
| 边界矩阵(守则 × 保留字 × reusability 三级距) | `b5437b1c7ab6f8c2` |

「完整推导结果」指的是整个 `derive()` 回传值 —— 三句话、来源方向、功能、
每一项分数、功能覆盖、最大相似度、被换掉的那一个与它的理由。
**取舍只要真的变了,就一定红。**

钉的是行为不是原始码,所以纯粹改注解、换排版不会误红。

## 2. 锁住的是哪些行为

| | |
| --- | --- |
| candidate derivation | 一句锚点 = 什么时候 + 可以往哪里看,两半都从已接受文案压缩 |
| scope guard | 那一步原本站在有保留的范围底下,就不从别句搬条件进来 |
| hedge handling | 语意判断,不要求保留字原样出现;保留字跟着那一步走时不受影响 |
| reusability | 回答「以后还回得来吗」的三级距 2 / 1 / 0,不是「有没有抓到场合片语」 |
| scoring | 忠于原文 → 能重复用 → 做得到 → 够具体 → 好记;长度只是最后的微调 |
| function classification | 回到自己 / 决定方向 / 早点发现,看这句话在讲什么,不看它来自哪个方向 |
| complementarity | 补上还没出现的功能是【加分】,不是硬性要求 |
| selection | 四个方向一律平等,Calls 够强就该被选上 |
| verifyDerived | 相邻两字回查:可以压缩、可以换顺序,不可以出现来源里没有的字词 |
| user-facing copy behavior | 画面上只有那三句话。来源方向 / 功能 / 取舍理由只给开发追溯 |

同时钉住的还有:`ANCHOR_COUNT === 3`、对外介面不被悄悄拿掉、
这一层**永远不呼叫任何 API**(原始码层面 + 执行期把 `fetch` 换成会抛错的桩)。

## 3. 目前的样本长什么样

已锁样本 `RAW_V12.C1`(compass-v1.2)选出来的三句:

```
✦  你发现自己一直停在再确认一下，也许可以先看看，现在到底是什么让你放不下心。   [drains / notice / 12.3]
✦  没力气的时候，可以先看看那个自己认同的理由还在不在，而不是先怀疑自己不够努力。 [moves  / orient / 12]
✦  先让自己安静一会儿就够了，不一定要马上解释。                            [grounds / return / 8.1]

被换掉:calls —— 「早点发现」已经有人选了,而且它的分数比较低(7)
```

`CALLS_WINS` 合成样本的存在只有一个理由:证明这个引擎【不会】永远变成
Grounds + Moves + Drains。那一份里 Calls 排第一,被换掉的是 Moves,
而且只覆盖两种功能 —— 互补是加分,不是硬性要求。

## 4. 要改做法的时候怎么做

**不要就地编辑这一版。** 开 `anchors-3.x`,把旧版留着,
把新版的指纹另外钉一组。就地改会让上面四个指纹立刻红,
而且失败讯息会直接指出是词表变了还是取舍结果变了。

## 5. 已知的边界

- 这一层只对 **compass-v1.2 形状**的文案有效(「什么时候 + 可以往哪里看」)。
  v1 / v1.1 的历史输出取不出候选,会回 `insufficient`,
  画面显示「等上面的内在指南生成之后……」——**不制造任何 fallback copy**。
- 功能分类是粗线条的词表,会有误判(例如「卡住的时候」被归成「早点发现」
  而不是「决定方向」)。后果是功能覆盖打折,不会产生错误内容。

## 6. anchors-3.1 —— 语意衍生层

`compass-v1` 那一代的文案只有【描述与归纳】,句子收在「这是怎么回事」,
没有一句收在「那下次可以怎么办」。已锁的 2.2 做的是【截取】,对它一句都取不出来。

第一次的补救(`anchors-3.0`)改用【拼接】:原文子字串 + 固定框架。它安全,
但读起来像拼的 —— 意思在原文里,句子却从来没有被真正重写过。
**人工内容审查没有通过,由 3.1 取代,不保留。**

### 换的是单位

```
3.0   每一个【字】都必须在来源里找得到
3.1   每一个【主张】都必须在来源里找得到
```

做法与这个专案既有的人话翻译层(`compass-translation.js`)同一套:

```
认出来源在讲哪一个【概念】 → 拿出我们【事先写好】的那一句
```

画面上每一个字都是人写的完整句子,不是原文的碎片。

### 安全性靠三件事,不靠逐字比对

| | |
| --- | --- |
| **概念授权** | 句子只有在它需要的概念【真的被这份文案授权】时才出现;`verifySemantic` 会重新授权一次 |
| **输出空间有限** | 概念 × 句型可枚举。全部 **19 句**列在测试里逐条审过、用 sha256 钉住 |
| **词典静态稽核** | 那些句子是我们写的,测试对【整本词典】扫一次人格主张 / 心理机制 / 成因 / 过去 / 情绪命名 / 星盘 / 玄学 / 万用句 / 命令句 |

第二点是 3.0 永远做不到的:它的输出空间是「原文的任意子字串组合」,无限大。

### 指纹

| 钉住的东西 | 指纹 |
| --- | --- |
| 概念词典 | `ba31ce40024aec21` |
| 句型 | `b9f9a5aea5974d3d` |
| 全部 19 句可能的输出 | `95f8abb7e7c55009` |

### 取舍的优先顺序(2026-09-16 人工 Voice Review 定案)

```
1 语意安全 / 可溯源   ← 词典与授权保证
2 自然                ← 手写 realization 保证
3 会不会想留给自己    ← keep,权重最大(×3)
4 具体 / 有用         ← spec
5 句型不要重复        ← 重复扣 1.5
6 功能互补            ← 只加 1
```

**第 6 项刻意给得比第 5 项小。功能互补是偏好,不是硬性规定 ——
不可以为了凑满 return + orient + notice 去挑一句明显更差的话。**
测试里有一条断言直接比较这两个数字;把它们对调会让案例 A 的第三席
从 Calls 翻回 Drains,四条断言立刻红。

### 语气守则

- 「也不迟 / 没关系 / 不急」这类宽慰,**只有在原文自己给了那个许可时**
  才准写进 realization,**不由句型自动加上去**。
- realization 的确定性不可以高过来源(沿用 2.1 的范围守则)。
  例:原文说「突然醒过来」,词典写的是「人**比较容易**回来」,不是「人就回来了」。

### 渲染时现算

三句话是四段文案的**纯函式**,所以页面不相信快取里那个阵列,
而是在渲染时现算(`compassAnchorsFor()`,以 `generatedAt` 记忆化)。
既有使用者那个空阵列**下次开页面就自己好了** —— 不必重新生成、不必清资料、0 次请求。
